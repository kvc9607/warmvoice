# 暖声 WarmVoice：算法复盘与设计记录

这份文档记录这条处理链为什么这样排、哪些环节被合并了、每一步花多少算力，以及模拟测试的实测结果。数字都是在开发机上实测的（Intel Xeon 2.1GHz，单核），不是估算。

## 1. 软件怎么接进 Windows

| 选择 | 原因 |
|---|---|
| 做成 APO（麦克风处理插件），不做虚拟声卡 | 虚拟声卡是内核驱动，必须有微软签名；APO 跑在普通权限下，不需要签名 |
| 装在 **EFX**（端点效果）位置 | 1）一个麦克风只处理一次，Discord 和游戏同时用麦也只算一份；2）微软文档写明 EFX 对"原始模式（raw）"的音频流也生效，SFX 对它不生效 |
| AI 库单独一个 DLL，运行时再加载 | 缺文件、电脑太慢或 AI 出错时，只是不降噪，其他步骤照常，不会没声音 |
| 所有分配内存的操作都放在 LockForProcess | 实时音频线程里不分配内存、不加锁、不等待 |

## 2. 处理顺序（第 2 版：只用 AI，不留省电模式）

```
麦克风（任意采样率、任意声道数）
 → 合成单声道 → 转成 48kHz
 → ① AI 降噪（DeepFilterNet 3）
       它每处理 10 毫秒，就把"降噪后"和"降噪前"的频谱交给我们的回调：
       · 动态去刺耳 / 去嘶声 / 去箱音（直接改降噪后的频谱）
       · 嗓音档案（降噪后的频谱）
       · 麦克风带宽检测（降噪前的频谱）
       有没有在说话：直接用 AI 给的信噪比
 → ② 高频修复（只在麦克风格式 ≥32kHz、内容却缺高频时开启）
 → ③ EQ：去低频嗡嗡声 + 音色预设和智能修正（合成 1 组 10 段）+ 用户 EQ 5 段
 → ④ 质感（2 倍过采样的谐波）
 → ⑤ 自动音量（看输出反馈调整）+ 压缩 + 防爆音，共用一个增益
 → 转回设备采样率 → 复制到所有声道
```

**每一步只做别人不做的事：**

| 事情 | 谁做 | 第 1 版的重复项（已删除） |
|---|---|---|
| 去噪音（包括停顿里的、键盘声） | AI | 省电版降噪 |
| 不说话时静音 | AI（降噪强度拉满 = 降噪深度 100dB） | 单独的自动静音模块和它的 20 毫秒预判 |
| 判断有没有在说话 | AI 的信噪比 | 单独的语音检测 |
| 分帧和 FFT | AI 内部那一次 | 自己的分帧、测带宽用的那次 FFT |
| 去刺耳、去嘶声 | 回调里的动态处理 | — |
| 补高频 | 高频修复（AI 不做这件事） | — |
| 音色 | 1 组 EQ | — |
| 音量、压缩、防爆音 | 1 个检测器、1 次乘法 | — |
| 麦克风本身的音量 | App 直接调 Windows 里的麦克风音量 | 数字输入增益（和自动音量重复） |

**AI 用不了怎么办**（文件丢失、出错、电脑太慢）：第 ① 步变成同样长度的延迟，只是不降噪，后面几步照常工作，延迟不变；界面会显示原因（`Analysis.aiProblem`：1 文件缺失 / 2 出错 / 3 电脑太慢）。这样声音不会断，也不会卡。

## 3. 合并掉的重复工作

| 原方案 | 现在 | 省了什么 |
|---|---|---|
| 降噪一次分帧，EQ、去嘶声再各自分帧 | 全部用 DeepFilterNet 同一次分帧（官方 C 接口加了一个回调） | 少一组 FFT，**也不增加延迟** |
| 噪声门 | 删掉，由 AI 的降噪深度负责 | 一个模块 |
| 语音检测 | 用 AI 的信噪比 | 一个模块 |
| 带宽检测单独做 FFT | AI 回调里直接给降噪前的频谱 | 一次 FFT |
| 去嘶声单独一个模块 | 并进动态处理 | 一次频段统计同时用于 3 件事 |
| 音色预设、智能修正各一组 EQ | 拟合合成同一组 10 段（拟合误差 0.4–0.7dB） | 两层合成一层 |
| 动态 EQ 放在 EQ 之后 | 放在之前，但"透过"后面 EQ 的响应来判断 | 能放在频谱里做，又不会判断错 |
| 自动音量、压缩、限幅各量一次电平 | 一个检测器，一次乘法 | — |
| "自动补偿"和"统一音量" | 删掉自动补偿 | 功能重复 |
| 数字输入增益 | 删掉（自动音量已经管了） | — |
| 半带过采样逐点卷积（每样本 93 次乘法） | 只算非零项（33 次） | "质感"开销从 0.28% 降到 0.08% |

## 4. 算力和延迟（实测，不含 AI 本身）

| 环节 | 单核占用（% 实时） |
|---|---|
| 回调里的频谱处理 | ≈0.05 |
| 高频修复（开启时） | 0.10–0.15 |
| EQ（1+10+5 段） | 0.13–0.21 |
| 质感 | 0.08–0.13 |
| 动态处理 | 0.03–0.06 |
| **合计（不含 AI）** | **约 0.5–0.9** |

- AI 本身的算力要在 GitHub 的 Windows 机器上用真正的 DeepFilterNet 量，结果会写进每次编译的汇总页。
- **延迟 41.7 毫秒**：AI 的分帧和往后看共 30 毫秒 + 积攒一帧 10 毫秒 + 质感和防爆音约 1.7 毫秒。

## 5. 让大多数电脑都能跑

- 只用 CPU，按 x86-64 基础指令集编译，不依赖显卡。
- 任何采样率（8k–384k）、1–16 声道。
- 每帧计时：AI 连续 2 秒占用超过 80% 的时间预算，就停掉 AI，只做其余几步；还不行就直通。
- 嗓音档案和带宽检测都是针对每个人自己的麦克风自动学的，不针对某个型号。
- 16kHz 格式的麦克风会自动关掉高频修复。

## 6. 第 1 版的模拟测试结果（标准降噪，作为参考）

测试素材：一段干净人声（freesound #33711，CC BY-NC，只用于测试，不随软件分发），配上合成的风扇噪音、机械键盘声，以及一段起伏很大的真实街道噪音。另外用滤波器模拟麦克风的发闷、箱音、偏薄，用重采样模拟无线传输丢高频。每个场景都先学习一遍嗓音档案，再处理。

**耳机麦**（小声 -34dBFS、发闷加箱音、风扇加键盘、48k 格式但内容只到 7kHz）：

| 指标 | 处理前 | 处理后 |
|---|---|---|
| 说话音量 | -33.7 dBFS | -19.9 dBFS（目标 -19） |
| 峰值 | -15.4 | -1.0（防爆音上限 -1） |
| 开头只有噪音的 1 秒 | -47.0 dBFS | 静音 |
| 句子之间的停顿 | -46.7 | -54.3 |
| 和真实嗓音的音色偏差 | 2.27 dB | 1.60 dB |
| 8–14kHz 高频（真实嗓音是 -12.4） | -65.1 | -18.3 |
| 被切掉开头的词 | — | 8 个里 2 个 |

**USB 麦**（正常音量、偏薄、风扇加键盘、全频带）：音量 -23.8 → -18.8；开头噪音段 → 静音；停顿 -44.1 → -65.2；音色偏差 2.03 → 2.21（**稍差**，见下面第 3 条）；没有词被切。

**复盘中发现并修掉的问题：**

1. 分贝取平均会偏低 3–4dB，导致输出偏响 → 改成按功率平均，之后又改成测量输出、反馈调整。
2. 标准降噪用第一帧估计噪音，导致启动后的 3 秒几乎不降噪 → 改成用开头 100 毫秒的平均值（降噪量从 12dB 提到 33dB）。
3. 智能优化会把人本身的嗓音特点也"修"掉 → 改成：整体偏闷或偏亮的倾斜全部修正，其余形状只修一半。USB 麦测试的结果仍然略差，说明参考曲线还需要用更多人的声音来调。
4. 高频修复在 16kHz 格式的设备上无效 → 自动关闭。
5. 带宽检测用的是降噪后的声音，会误判截止频率 → 改成用原始信号（16k 内容测出 7.3kHz，24k 测出 11.4kHz，全频带不会误判）。
6. 一下键盘声被当成说话，导致自动音量猛增 20dB → 累计 0.3 秒确认是人声后才开始调整，第一次调整最多 +12dB。
7. 标准模式下，键盘声会让自动静音一直开着 → 往后看 20 毫秒，连续 30 毫秒像人声才开麦，连续 2 帧像人声才保持；关麦分两级（先压低 24dB，停满 1.5 秒才完全静音）。
8. "质感"的抽取取在奇数位置，比原声晚了半个样本，混合时会互相抵消；去直流滤波器作用在了整个信号上 → 已修正，并加了测试。

第 2 版去掉了标准降噪，降噪改由 AI 负责；AI 版的同一套测试在 GitHub 上自动运行（`scripts/e2e.sh`），结果见每次编译的汇总页和 `e2e-results` 文件包。

## 6a. 第 2 版实测（真 AI，GitHub Windows 机器）

测试方式和第 6 节相同，但降噪换成真正的 DeepFilterNet 3。CPU 是 GitHub 云端 Windows 机器单核的占用，**包括 AI 在内的整条链**。

| 场景 | 延迟 | CPU | 说话音量 | 停顿噪音 | 音色偏差 | 8–14kHz 高频 | 嗓音档案 |
|---|---|---|---|---|---|---|---|
| 耳机 + 风扇 | 41.7 ms | 4.2 % | -33.7 → -21.9 | -46.1 → -72.0 | 3.13 → 1.03 | -65.0 → -21.4 | 735 帧 |
| 耳机 + 键盘 | 41.7 ms | 4.0 % | -33.8 → -20.4 | -48.2 → -73.0 | 1.88 → 1.12 | -65.2 → -22.7 | 1067 帧 |
| 耳机 + 风扇和键盘 | 41.7 ms | 4.1 % | -33.7 → -22.0 | -46.7 → -72.5 | 2.27 → 1.36 | -65.1 → -23.4 | 719 帧 |
| USB + 风扇 | 41.7 ms | 4.0 % | -23.8 → -20.1 | -43.9 → -69.7 | 2.00 → 1.68 | -13.7 → -11.7 | 1145 帧 |
| USB + 键盘 | 41.7 ms | 4.0 % | -23.8 → -19.2 | -44.3 → -73.3 | 2.08 → 1.62 | -13.4 → -11.3 | 1406 帧 |
| USB + 风扇和键盘 | 41.7 ms | 4.1 % | -23.8 → -20.0 | -44.1 → -69.5 | 2.03 → 1.68 | -13.6 → -11.8 | 1150 帧 |

- 单元测试：停顿噪音 -40.3 → -80.7 dB（AI 去掉的 40dB 经过整条链完整保留）。
- 键盘声在 AI 下被去掉了（停顿 -73dB），第 1 版标准降噪做不到。
- 6 个场景的音色偏差全部变小，包括第 1 版变差的 USB 场景。
- 待调：耳机场景输出比目标 -19.2 低 2–3dB。原因是 AI 只把有把握的帧算作说话，自动音量据此估计的电平偏高。

## 7. 还没验证的部分

| 项目 | 状态 | 怎么验证 |
|---|---|---|
| AI 降噪（DeepFilterNet） | 已在 Windows 上编译并通过测试（见 6a） | — |
| APO 插件、安装工具 | 已在 Windows 上编译通过；还没在真机上装到麦克风 | 在你的电脑上运行 wvinstall |
| "音频增强"开关在注册表里的位置 | 用的是 SDK 的官方常量，所以属性键本身不会错；写在 FxProperties 下面要到真机上确认 | `wvinstall list` 之后查看 |
| 厂商自带的麦克风效果（比如笔记本的阵列麦） | 现在是替换（会备份，卸载时恢复），还不能和厂商效果串联 | 第二版 |
| 音色参考曲线 | 只用一个人的声音调过 | 用你自己的声音和更多公开语音数据来调 |
